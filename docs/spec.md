# MOZI 기능 동작 명세서

## 1. 문서 목적

이 문서는 [MVP 기획서](./mvp.md)에 확정된 MOZI의 기능이 사용자와 시스템 관점에서 어떻게 동작해야 하는지 정의한다.

- `mvp.md`는 무엇을 만들지 설명한다.
- `spec.md`는 각 기능의 입력, 처리, 결과, 실패 상황과 권한을 정의한다.
- 이 문서에 없는 기능은 MVP 구현 중 임의로 추가하지 않는다.
- 공개 배포 환경은 아직 결정하지 않았으므로 로컬과 배포 환경에서 공통으로 사용할 수 있게 설계한다.

## 2. 공통 기준

### 2.1 사용자 구분

| 사용자 | 할 수 있는 일 |
| --- | --- |
| 비로그인 사용자 | 랜딩, 회원가입, 로그인, 활성화된 캐릭터 공유 페이지 보기 |
| 로그인 사용자 | 자신의 일기, 캐릭터, 도감, 감정 방, 공유 링크와 계정 설정 사용 |

다른 사용자의 비공개 데이터는 ID나 URL을 직접 입력해도 조회할 수 없어야 한다.

### 2.2 날짜와 시간

- 일기 날짜와 하루 한 번 제한은 `Asia/Seoul` 기준으로 계산한다.
- 서버가 최종 날짜를 판단하며 브라우저가 보낸 날짜를 신뢰하지 않는다.
- 데이터베이스의 시각은 시간대 정보가 있는 값으로 저장한다.
- 사용자 화면에는 한국 날짜 형식으로 표시한다.

### 2.3 공통 상태 처리

모든 주요 화면에는 다음 상태가 있어야 한다.

- 로딩 중
- 데이터 없음
- 정상 표시
- 입력 오류
- 서버 오류
- 네트워크 오류

실패했는데 성공한 것처럼 화면을 바꾸면 안 된다. 저장 실패 시 사용자가 입력한 내용을 가능한 한 유지한다.

### 2.4 공통 응답 원칙

- 인증이 없으면 인증 실패로 처리한다.
- 자신의 데이터가 아니거나 존재하지 않는 데이터는 외부에 차이를 드러내지 않는다.
- 사용자에게는 이해하기 쉬운 한국어 안내를 보여준다.
- 서버 내부 경로, SQL, API 키, 스택 추적과 일기 원문을 오류 응답에 포함하지 않는다.

## 3. 화면과 이동 구조

### 3.1 주요 경로

정확한 URL은 구현 중 프레임워크 구조에 맞출 수 있으나 역할은 다음과 같이 유지한다.

| 화면 | 권한 | 역할 |
| --- | --- | --- |
| 랜딩 | 모두 | 서비스 소개와 가입·로그인 진입 |
| 회원가입 | 비로그인 | 이메일, 비밀번호, 닉네임으로 가입 |
| 로그인 | 비로그인 | 이메일과 비밀번호로 로그인 |
| 나의 감정 방 | 로그인 | 로그인 후 기본 홈 |
| 일기 작성 | 로그인 | 오늘의 일기 작성과 캐릭터 생성 시작 |
| 생성 진행 | 로그인 | AI 분석과 캐릭터 조합 상태 표시 |
| 오늘의 결과 | 로그인 | 오늘의 캐릭터와 감정 결과 표시 |
| 캐릭터 도감 | 로그인 | 소유한 캐릭터 목록 표시 |
| 캐릭터 상세 | 로그인 | 이름, 만남 목록, 입주·공유·삭제 관리 |
| 만남 상세 | 로그인 | 특정 날짜의 일기와 분석 결과 표시 |
| 입주 관리 | 로그인 | 감정 방 캐릭터 최대 5마리 선택 |
| 공유 페이지 | 모두 | 공유된 캐릭터만 표시 |
| 계정 설정 | 로그인 | 닉네임 변경, 로그아웃, 회원 탈퇴 |

### 3.2 로그인 후 최초 이동

- 로그인 성공 후 `나의 감정 방`으로 이동한다.
- 보호된 화면에 접근하다 로그인한 경우에도 MVP에서는 감정 방으로 이동한다.
- 이미 로그인한 사용자가 회원가입 또는 로그인 화면에 접근하면 감정 방으로 이동한다.

## 4. 회원 기능

### 4.1 회원가입

#### 입력

| 항목 | 규칙 |
| --- | --- |
| 이메일 | 앞뒤 공백 제거, 일반적인 이메일 형식, 대소문자를 구분하지 않고 중복 확인 |
| 비밀번호 | 입력 그대로 검사, 8~64자 |
| 닉네임 | 앞뒤 공백 제거, 1~20자, 한글·영문·숫자·밑줄만 허용 |

#### 성공

1. 이메일과 닉네임 중복을 검사한다.
2. 비밀번호를 검증된 비밀번호 해시 방식으로 처리한다.
3. 사용자 계정을 만든다.
4. 자동 로그인하지 않고 로그인 화면으로 이동한다.
5. `회원가입이 완료되었습니다. 로그인해 주세요.`라고 안내한다.

#### 실패

- 이미 사용 중인 이메일이면 다른 이메일을 사용하도록 안내한다.
- 이미 사용 중인 닉네임이면 다른 닉네임을 사용하도록 안내한다.
- 형식이나 길이 조건이 맞지 않으면 해당 입력칸 가까이에 이유를 표시한다.
- 실패 시 이메일과 닉네임은 유지하고 비밀번호만 비운다.
- 동시에 들어온 두 가입 요청으로 중복 계정이 생기지 않게 데이터베이스 유일 제약을 둔다.

### 4.2 로그인

#### 입력

- 이메일
- 비밀번호

#### 성공

- 이메일과 비밀번호가 맞으면 서버 세션을 만든다.
- 세션 식별자는 HTTP-only 쿠키로 전달한다.
- 감정 방으로 이동한다.

#### 실패

- 이메일이 없거나 비밀번호가 틀려도 `이메일 또는 비밀번호가 맞지 않습니다.`라는 같은 안내를 사용한다.
- 실패 시 이메일은 유지하고 비밀번호만 비운다.
- 인증 실패에 비밀번호나 계정 존재 여부를 자세히 노출하지 않는다.

### 4.3 세션 쿠키

- JavaScript로 읽을 수 없는 HTTP-only 쿠키를 사용한다.
- 로컬 개발과 실제 배포의 `Secure`, `SameSite`, 도메인 설정은 환경 변수로 구분한다.
- 세션 만료 기간은 MVP 기본 7일로 한다.
- 로그아웃, 회원 탈퇴와 만료 시 세션을 사용할 수 없게 한다.
- 비밀번호 해시나 API 키를 쿠키에 넣지 않는다.

### 4.4 로그아웃

- 로그아웃을 누르면 현재 세션을 서버에서 무효화한다.
- 쿠키를 제거하고 랜딩 화면으로 이동한다.
- 로그아웃 후 뒤로 가기로 보호된 화면을 다시 사용할 수 없어야 한다.

### 4.5 닉네임 변경

- 현재 사용자만 자신의 닉네임을 변경할 수 있다.
- 회원가입과 같은 길이·문자·중복 규칙을 적용한다.
- 성공하면 계정 화면과 공유 페이지에 새 닉네임을 표시한다.
- 과거 공유 데이터에 닉네임 문자열을 복사해 두지 않고 현재 사용자 닉네임을 읽는다.

### 4.6 회원 탈퇴

#### 입력과 확인

1. 삭제되는 데이터 목록을 보여준다.
2. 현재 비밀번호를 입력한다.
3. `탈퇴합니다` 문구를 정확히 입력한다.
4. 최종 탈퇴 버튼을 누른다.

#### 성공

- 사용자의 일기, 분석, 캐릭터, 만남, 입주 정보와 공유 링크를 삭제한다.
- 모든 로그인 세션을 무효화한다.
- 랜딩 화면으로 이동한다.
- 다시 접근한 공유 링크는 캐릭터가 없다는 일반 안내를 보여준다.

#### 실패

- 비밀번호가 틀리거나 확인 문구가 다르면 삭제하지 않는다.
- 일부 데이터만 삭제되는 상태가 생기지 않도록 하나의 데이터베이스 작업 단위로 처리한다.
- 탈퇴 처리에 실패하면 로그인 상태와 기존 데이터를 유지하고 재시도를 안내한다.

## 5. 오늘의 일기

### 5.1 일기 상태

하루의 기록은 다음 상태 중 하나다.

| 상태 | 의미 | 가능한 행동 |
| --- | --- | --- |
| 미작성 | 오늘 아직 생성하지 않음 | 일기 작성 |
| 작성 중 | 브라우저 입력 단계 | 수정, 생성 요청 |
| 분석 중 | 서버가 분석 작업을 처리 중 | 진행 상태 확인 |
| AI 실패 | 실제 분석 실패 | 다시 시도, 데모 분석 선택 |
| 생성 완료 | 일기와 캐릭터 확정 | 읽기, 공유, 삭제 |
| 삭제됨 | 오늘 기록을 삭제함 | 새 기록 생성 불가 |

### 5.2 작성 화면

- 오늘 날짜를 자동 표시하며 사용자가 날짜를 바꿀 수 없다.
- 입력란 아래에 `현재 글자 수 / 2,000`을 표시한다.
- 앞뒤 공백을 제거한 결과가 10자 미만이면 생성 버튼을 활성화하지 않는다.
- 2,000자를 넘는 추가 입력을 막거나 즉시 오류를 표시한다.
- 오늘 생성 완료 또는 삭제 기록이 있으면 작성 화면 대신 오늘의 상태를 안내한다.

### 5.3 생성 확인

`캐릭터 생성하기`를 누르면 다음 내용을 확인한다.

```text
캐릭터를 생성하면 오늘의 일기와 감정 기록이 확정됩니다.
생성 후에는 일기를 수정하거나 캐릭터를 다시 뽑을 수 없습니다.
```

- `계속 작성하기`를 누르면 입력 화면으로 돌아간다.
- `확정하고 생성하기`를 누르면 서버에 요청한다.
- 확정 요청 이후 버튼을 비활성화해 중복 제출을 막는다.

### 5.4 하루 한 번 제한

- 데이터베이스에서 사용자와 한국 날짜 조합을 유일하게 제한한다.
- 여러 탭에서 동시에 생성해도 일일 기록은 하나만 생겨야 한다.
- 성공 응답이 유실되어 사용자가 다시 요청해도 기존 결과를 반환한다.
- 삭제 후에는 원문과 분석을 제거하되 해당 날짜에 생성했다는 최소 표식을 유지한다.

### 5.5 수정과 삭제

- 생성 전 브라우저 입력은 자유롭게 고칠 수 있다.
- 생성 완료 후 서버의 일기 수정 기능은 제공하지 않는다.
- 삭제 전 복구할 수 없다는 안내와 확인을 받는다.
- 삭제한 날짜의 기록은 다시 만들 수 없다.
- 해당 캐릭터가 다른 날짜에도 등장했다면 그 날짜의 만남만 제거한다.
- 마지막 만남이라면 캐릭터, 입주 정보와 공유 링크도 제거한다.

### 6.4 구조화된 결과

AI 결과는 다음 의미를 가진 구조로 검증한다.

```json
{
  "schemaVersion": 1,
  "baseEmotions": {
    "joy": 18,
    "excitement": 72,
    "calm": 12,
    "pride": 8,
    "moved": 20,
    "sadness": 4,
    "anger": 2,
    "irritation": 6,
    "anxiety": 48,
    "loneliness": 5,
    "disappointment": 3,
    "embarrassment": 16,
    "confusion": 14,
    "shyness": 22,
    "fatigue": 10,
    "lethargy": 3
  },
  "primaryEmotion": "excitement",
  "secondaryEmotions": ["anxiety", "shyness"],
  "detailStates": [
    {
      "key": "anticipation",
      "confidence": 82
    }
  ],
  "energy": 68,
  "keywords": [
    {
      "text": "연락",
      "category": "social"
    }
  ],
  "eventSummary": "기다리던 연락을 받아 설레면서도 긴장함"
}
```

#### 검증 규칙

- 16개의 기본 감정 키가 모두 있어야 한다.
- 각 점수, 세부 상태 신뢰도와 에너지는 0~100 정수다.
- 주요 감정은 기본 감정 중 최고 의미 점수를 가진 하나다.
- 보조 감정은 주요 감정과 다른 최대 2개다.
- 세부 상태는 허용 목록에서 최대 3개다.
- 키워드는 최대 5개이며 미리 정한 장식 분류로 변환한다.
- 사건 요약은 내부와 소유자 상세 화면에서만 사용하며 공유하지 않는다.
- 스키마 검증에 실패하면 캐릭터를 생성하지 않고 분석 실패로 처리한다.

### 6.5 화면 표시용 감정 비율

- 기본 점수 전체는 내부에 보존한다.
- 캐릭터 구성에 실제로 사용한 의미 있는 감정만 최대 3개 고른다.
- 점수가 매우 낮은 감정은 억지로 세 번째 감정으로 표시하지 않는다.
- 선택된 감정 점수의 비율을 합계 100%가 되도록 반올림한다.
- 반올림 오차는 가장 큰 감정에 더하거나 빼서 합계를 100으로 맞춘다.
- 화면에 1개만 표시될 경우 100%, 2개면 두 값의 합계가 100%가 된다.

### 6.6 데모 분석기

- 실제 AI와 같은 결과 스키마를 반환한다.
- 감정 단어, 부정·긍정 표현과 에너지 표현을 규칙으로 분석한다.
- 분석할 수 없는 글에는 중립 기본값과 낮은 신뢰도를 사용한다.
- 데모 결과임을 데이터에 기록하고 사용자에게 표시한다.
- 데모 모드도 일일 생성 횟수를 소비하며 다시 뽑을 수 없다.

## 7. 캐릭터 생성 명세

### 7.1 캐릭터와 만남의 구분

- `캐릭터`는 여러 날 다시 등장할 수 있는 고유한 친구다.
- `만남`은 특정 날짜의 일기와 캐릭터가 연결된 기록이다.
- 같은 캐릭터가 재등장해도 캐릭터 카드는 하나만 유지한다.
- 날짜별 감정 강도, 장식과 대사는 만남에 저장한다.

### 7.2 감정 강도 단계

| 점수 | 내부 단계 | 표시 의미 |
| ---: | --- | --- |
| 0~19 | 1 | 미약 |
| 20~39 | 2 | 약함 |
| 40~59 | 3 | 보통 |
| 60~79 | 4 | 강함 |
| 80~100 | 5 | 극대화 |

### 7.3 감정 지문

MVP 감정 지문은 다음 값을 순서대로 결합한다.

```text
주요 감정 키
+ 주요 감정 강도 단계
+ 첫 번째 보조 감정 키 또는 none
+ 가장 높은 세부 상태 키 또는 none
+ 에너지 단계
```

에너지 단계도 감정 강도와 같은 5단계를 사용한다.

- 같은 사용자에게 같은 지문이 있으면 기존 캐릭터를 재사용한다.
- 같은 지문이 없으면 새 캐릭터를 만든다.
- 사용자별 고유값과 감정 지문을 함께 해시해 캐릭터 랜덤 시드를 만든다.
- 일기 원문을 랜덤 시드에 직접 넣지 않는다.
- 키워드 장식은 감정 지문에 포함하지 않아 다른 사건에서도 같은 캐릭터가 재등장할 수 있게 한다.

초기 시연에서 너무 자주 같은 캐릭터가 나오면 세부 상태를 더 엄격히 구분하고, 너무 자주 새 캐릭터가 나오면 보조 감정 또는 에너지 단계를 지문에서 완화한다. 이 변경은 알고리즘 버전으로 관리한다.

### 7.4 파츠 수량 기준

MVP의 최소 목표 수량은 다음과 같다.

| 파츠 | 최소 수량 | 비고 |
| --- | ---: | --- |
| 몸통 형태 | 1 | 모든 캐릭터가 96:64 비율의 공통 기본 젤리형을 사용 |
| 기본 색상 계열 | 8 | 감정별 가중치를 적용 |
| 눈썹 | 8 | 감정 레시피에서 재사용 |
| 눈 | 12 | 기본·반눈·별·촉촉함·소용돌이 등 |
| 입 | 10 | 미소·활짝 웃음·일자·하품·울먹임 등 |
| 장식 분류 | 10 | work, study, drink, social, nature 등 |
| 감정 효과 | 8 | 눈물, 땀, 하트, 불꽃, 반짝임 등 |
| 돌연변이 | 5 | 뿔, 귀, 꼬리, 반점 등 |

수량보다 모든 조합에서 위치와 크기가 맞는 것을 우선한다.

### 7.5 픽셀 레이어 규칙

- 모든 파츠는 40×40 논리 격자를 160×160 PNG로 4배 확대한 같은 기준 좌표를 사용한다. 몸통 실루엣은 가이드의 96:64 비율을 이 캔버스에 맞게 정규화한다.
- 확대는 nearest-neighbor만 사용하고 표시 시 `image-rendering: pixelated`를 적용한다.
- 선은 굵고 어두운 공통 외곽선을 사용한다.
- 몸통은 상단이 단조 증가·감소하는 고정 마스크로 생성해 중앙 파임을 구조적으로 차단한다.
- 공통 몸통 마스크는 연결 영역 1개, 내부 구멍 0개, 볼록한 상단, 얇은 하단 물결을 자동 검증한다.
- 파츠는 `몸통 → 색상 → 얼굴 → 앞쪽 장식 → 효과` 순서로 겹친다.
- 캐릭터 외형은 허용된 PNG 파츠 ID와 색상, 시드로 재현한다.

### 7.6 표정 조합

1. 주요 감정이 기본 몸통 색상, 기본 눈과 입을 결정한다.
2. 보조 감정은 눈썹, 눈, 입 중 주요 감정과 충돌이 적은 하나를 변경한다.
3. 가장 높은 세부 상태가 전용 파츠 또는 효과를 덧붙인다.
4. 강도 단계가 눈·입의 과장 버전과 효과 수를 조절한다.
5. 세부 상태와 보조 감정이 충돌하면 세부 상태를 우선한다.
6. 결과가 조립 불가능하면 해당 주요 감정의 안전한 기본 표정으로 대체한다.

### 7.7 색상과 랜덤 요소

- 주요 감정마다 선호 색상 계열과 가중치를 둔다.
- 감정이 같다고 항상 한 색만 사용하지 않는다.
- 몸통 형태는 공통 기본 젤리형으로 고정하고 색상·표정·장식·돌연변이를 캐릭터 시드로 결정한다.
- 돌연변이는 낮은 확률로 적용하되 같은 캐릭터가 다시 등장하면 유지한다.
- 키워드 장식은 만남별로 달라질 수 있다.

### 7.8 이름 생성과 변경

- 새 캐릭터에 감정, 행동 또는 장식 단어를 조합한 한국어 기본 이름을 만든다.
- 이름 생성 실패 시 안전한 후보 목록에서 선택한다.
- 기본 이름도 캐릭터 생성 결과에 저장해 다시 열 때 바뀌지 않게 한다.
- 사용자는 1~12자의 이름으로 변경할 수 있다.
- 앞뒤 공백은 제거한다.
- 화면에 출력할 때 HTML로 실행되지 않게 안전하게 처리한다.
- 이름 변경은 일기와 캐릭터 외형을 바꾸지 않는다.

### 7.9 중복 생성 방지

- 일일 기록 생성 요청에 서버가 멱등성을 보장한다.
- 분석은 성공했지만 응답이 끊긴 경우 다음 요청에서 기존 결과를 반환한다.
- 캐릭터와 만남 생성은 하나의 데이터베이스 작업으로 처리한다.
- 실패 시 캐릭터만 있고 만남이 없는 불완전 데이터를 남기지 않는다.

## 8. 캐릭터 결과와 도감

### 8.1 결과 화면

다음 순서로 보여준다.

1. 캐릭터 공개 연출
2. 움직이는 캐릭터
3. 캐릭터 이름
4. 상위 감정 최대 3개와 표시 비율
5. 짧은 특징 설명
6. 도감에서 보기
7. 빈 입주 자리가 있을 때 방에 입주시키기
8. 공유하기

캐릭터는 결과 화면에 도착하기 전에 이미 도감에 저장되어 있어야 한다.

### 8.2 도감 목록

- 사용자가 소유한 캐릭터만 표시한다.
- 기본 정렬은 최근에 만난 순서다.
- 카드에는 캐릭터, 현재 이름, 주요 감정 성격, 만난 횟수와 입주 여부를 표시한다.
- 같은 캐릭터의 여러 만남을 여러 카드로 만들지 않는다.
- 데이터가 없으면 첫 일기 작성을 안내한다.

### 8.3 캐릭터 상세

- 캐릭터 기본 외형과 모션
- 현재 이름과 이름 변경
- 처음 만난 날, 최근 만난 날, 만난 횟수
- 입주·퇴실 상태
- 공유 링크 생성·복사·취소
- 만남 날짜 목록
- 캐릭터 삭제로 이어질 수 있는 만남 삭제 안내

### 8.4 만남 상세

- 해당 캐릭터와 해당 사용자의 만남인지 서버가 확인한다.
- 날짜, 일기 원문, 표시용 감정, 세부 상태, 그날의 장식과 대사를 보여준다.
- 수정 기능은 제공하지 않는다.
- 공유 페이지로 연결되는 버튼은 캐릭터만 공유한다는 점을 알려준다.
- 날짜별 만남 삭제를 제공한다.

## 9. 나의 감정 방

### 9.1 방 기본 구성

- 정면에서 바라보는 2D 픽셀 방 한 종류를 사용한다.
- 큰 화면에서는 방을 넓게, 작은 화면에서는 비율을 유지한 채 축소한다.
- 캐릭터는 방의 이동 허용 영역 안에서만 움직인다.
- 방 아래에 `일기 쓰기`, `캐릭터 도감`, `입주 관리`를 배치한다.
- 입주 수를 `3 / 5 입주`처럼 표시한다.

### 9.2 입주 관리

- 도감의 모든 캐릭터를 카드로 표시한다.
- 각 카드에 `입주 중` 또는 `대기 중` 상태를 표시한다.
- 대기 중 캐릭터를 누르면 빈자리가 있을 때 입주시킨다.
- 입주 중 캐릭터를 누르면 퇴실시킬 수 있다.
- 5마리가 입주 중이면 새 입주를 막고 먼저 한 마리를 퇴실시키도록 안내한다.
- 입주와 퇴실은 캐릭터나 만남 기록을 삭제하지 않는다.
- 여러 요청이 동시에 와도 사용자당 입주 캐릭터가 5마리를 넘을 수 없게 서버에서 확인한다.

### 9.3 행동 유형

| 유형 | 기본 이동 | 기본 대기 행동 |
| --- | --- | --- |
| 활발형 | 빠르고 비교적 긴 이동 | 통통 뛰기 |
| 평온형 | 느리고 부드러운 이동 | 숨 쉬듯 움직이기 |
| 지침형 | 느리고 짧은 이동 | 졸기 또는 앉기 |
| 정지형 | 거의 이동하지 않음 | 멍하니 서 있기 |
| 격앙형 | 짧고 빠른 왕복 | 떨기 또는 발 구르기 |
| 불안정형 | 중간 속도, 방향 자주 변경 | 두리번거리기 |

- 주요 감정이 행동 유형을 결정한다.
- 세부 상태가 명확하면 행동 유형을 보정할 수 있다.
- 감정 강도가 높을수록 속도, 반복 횟수 또는 움직임 크기가 증가한다.
- 피로·무기력 계열은 강도가 높을수록 오히려 이동 빈도가 감소한다.

### 9.4 이동 방식

- 게임 엔진을 사용하지 않는다.
- 각 캐릭터가 일정 시간마다 허용 영역 안의 목표 좌표를 선택한다.
- CSS transform 또는 SVG transform으로 이동한다.
- 정교한 가구 충돌, 캐릭터 간 충돌과 길 찾기는 구현하지 않는다.
- 겹침이 심하지 않도록 시작 위치와 목표 위치에 간단한 간격만 적용한다.
- 화면을 다시 열면 좌표는 바뀔 수 있으며 입주 목록만 영구 저장한다.

### 9.5 말풍선

- 캐릭터를 누르면 감정별 후보 중 한 문장을 보여준다.
- 한 번에 해당 캐릭터의 말풍선 하나만 표시한다.
- 몇 초 후 자동으로 사라진다.
- 대사는 일기 원문과 구체적인 개인 정보를 포함하지 않는다.
- 같은 캐릭터라도 최근 만남의 주요 감정과 세부 상태에 맞는 후보를 사용한다.

### 9.6 움직임 접근성

- 운영체제의 움직임 감소 설정을 존중한다.
- 움직임 감소 환경에서는 자동 이동 거리를 줄이거나 정지 상태와 약한 대기 모션만 사용한다.
- 번쩍이는 빠른 효과를 사용하지 않는다.

## 10. 캐릭터 공유

### 10.1 공유 생성

- 캐릭터 소유자만 공유 링크를 만들 수 있다.
- 한 캐릭터에 활성 공유 링크 하나를 재사용한다.
- 공유 토큰은 순차 ID가 아닌 추측하기 어려운 무작위 값이다.
- 링크 복사와 모바일 기본 공유 기능을 제공한다.

### 10.2 공유 페이지

표시 정보:

- `OOO님이 새로운 감정 몬스터를 공유했어요!`
- 공유자의 현재 닉네임
- 캐릭터 현재 이름
- 캐릭터 기본 외형과 모션
- MOZI 로고 또는 서비스 이름
- `나도 감정 몬스터 만들기` 버튼

표시하지 않는 정보:

- 일기 원문과 요약
- 작성 날짜
- 감정 이름, 점수와 분석 결과
- 키워드와 사건
- 이메일, 사용자 ID와 다른 캐릭터

### 10.3 공유 취소와 삭제

- 소유자는 공유를 취소할 수 있다.
- 취소한 토큰은 다시 활성화하지 않고 필요하면 새 토큰을 만든다.
- 캐릭터 삭제 또는 회원 탈퇴 시 공유 링크도 사용할 수 없게 한다.
- 비활성 링크는 데이터 존재 여부를 자세히 밝히지 않고 일반적인 만료 안내를 보여준다.

### 11.3 daily_entries

## 12. API 역할 명세

정확한 URL은 구현 계획에서 확정하되 다음 역할을 분리한다.

### 12.1 인증·계정

- 회원가입
- 로그인
- 로그아웃
- 현재 사용자 조회
- 닉네임 변경
- 회원 탈퇴

### 12.2 일기·분석

- 오늘 상태 조회
- 오늘 일기 확정 및 실제 AI 분석 시작
- 실제 AI 분석 재시도
- 데모 분석으로 계속하기
- 오늘 결과 조회
- 만남 기록 삭제

### 12.3 캐릭터·도감

- 내 캐릭터 목록
- 내 캐릭터 상세
- 캐릭터 이름 변경
- 캐릭터 만남 목록과 상세
- 입주·퇴실 변경
- 현재 입주 캐릭터 목록

### 12.4 공유

- 공유 링크 생성 또는 기존 활성 링크 조회
- 공유 취소
- 공개 토큰으로 캐릭터 자랑 카드 조회

모든 개인 API는 서버에서 현재 사용자와 데이터 소유자를 비교한다. 클라이언트가 보낸 `user_id`를 소유권 판단에 사용하지 않는다.

## 13. 환경 변수

실제 이름은 구현 시 통일하되 최소한 다음 종류가 필요하다.

```text
APP_ENV
FRONTEND_URL
BACKEND_URL
DATABASE_URL
SESSION_COOKIE_NAME
SESSION_TTL_DAYS
OPENAI_API_KEY
AI_ANALYSIS_MODE
```

- 실제 값은 `.env`에 둔다.
- `.env.example`에는 변수 이름과 안전한 예시만 둔다.
- `.env`, 로컬 데이터베이스, 로그와 생성 파일은 Git에서 제외한다.
- `AI_ANALYSIS_MODE`는 실제 분석 가능 여부를 제어하되 사용자의 선택 없는 자동 위장은 허용하지 않는다.

## 14. 반응형·접근성 기준

- 최소 360px 너비에서 핵심 기능을 사용할 수 있어야 한다.
- 작은 화면에서는 카드와 폼을 한 열로 배치한다.
- 방은 원본 비율을 유지하고 캐릭터 클릭 영역이 지나치게 작아지지 않게 한다.
- 키보드로 주요 버튼과 폼을 사용할 수 있어야 한다.
- 입력 오류는 색상만이 아니라 글자로도 안내한다.
- 캐릭터 감정은 색상만이 아니라 표정과 효과로도 구분한다.
- 버튼과 본문은 읽기 쉬운 대비를 유지한다.
- 움직임 감소 설정을 지원한다.

## 15. 보안·개인정보 확인 항목

- 비밀번호 원문이 DB, 로그, 응답에 남지 않는다.
- OpenAI API 키가 프론트엔드 번들에 포함되지 않는다.
- 일기 원문을 일반 서버 로그에 남기지 않는다.
- 사용자 A가 사용자 B의 일기, 분석, 캐릭터 관리 API를 사용할 수 없다.
- 공유 페이지는 캐릭터와 닉네임 외의 비공개 정보를 반환하지 않는다.
- 공유 토큰을 추측하거나 순서대로 조회할 수 없다.
- 이름과 닉네임을 화면에 표시할 때 코드로 실행되지 않는다.
- 회원 탈퇴와 마지막 만남 삭제가 관련 공유 링크와 입주 정보를 함께 정리한다.
- AI 결과를 의학적 진단으로 표현하지 않는다.

## 16. 핵심 테스트 시나리오

### 16.1 회원

- 서로 다른 이메일과 닉네임으로 가입한다.
- 같은 이메일 또는 닉네임으로 가입하지 못한다.
- 비밀번호 8자와 64자는 허용하고 7자와 65자는 거부한다.
- 가입 성공 후 로그인 화면으로 이동한다.
- 올바른 계정만 로그인할 수 있다.
- 로그아웃 후 보호된 화면에 접근하지 못한다.
- 닉네임 변경이 공유 페이지에도 반영된다.
- 잘못된 비밀번호로 회원 탈퇴할 수 없다.

### 16.2 일기와 분석

- 9자, 10자, 2,000자, 2,001자 입력 경계를 확인한다.
- 같은 사용자가 같은 날 두 기록을 만들 수 없다.
- 여러 탭에서 동시에 요청해도 하나만 생성된다.
- 생성 완료 후 일기를 수정할 수 없다.
- 실제 AI 성공 결과가 스키마 검증을 통과한다.
- 잘못된 AI 결과가 캐릭터 생성으로 이어지지 않는다.
- AI 실패 후 다시 시도와 데모 모드를 각각 사용할 수 있다.
- 삭제 후 같은 날 새 기록을 만들 수 없다.

### 16.3 캐릭터와 도감

- 같은 사용자와 같은 감정 지문에서 같은 캐릭터가 재등장한다.
- 다른 감정 지문에서는 새 캐릭터가 생성된다.
- 다른 사용자의 같은 감정 지문은 사용자별 시드로 구분된다.
- 같은 캐릭터 재등장 시 카드가 늘지 않고 만남 횟수만 증가한다.
- 이름 변경 후 다시 로그인해도 이름이 유지된다.
- 마지막 만남을 삭제하면 캐릭터와 관련 공유·입주 정보가 제거된다.
- 기존 만남이 남아 있으면 해당 날짜만 삭제되고 캐릭터는 유지된다.

### 16.4 감정 방

- 최대 5마리까지 입주할 수 있다.
- 6번째 입주 요청을 서버가 거부한다.
- 입주와 퇴실 후 다시 로그인해도 상태가 유지된다.
- 행동 유형별 속도와 대기 동작이 구분된다.
- 캐릭터가 방의 허용 영역을 벗어나지 않는다.
- 움직임 감소 설정에서 과한 이동이 줄어든다.

### 16.5 공유와 권한

- 소유자만 공유 링크를 생성하고 취소할 수 있다.
- 비로그인 사용자가 활성 공유 링크를 볼 수 있다.
- 공유 응답에 일기, 감정 점수, 사용자 ID와 이메일이 없다.
- 공유 취소, 캐릭터 삭제와 회원 탈퇴 후 링크가 비활성화된다.
- 다른 사용자의 캐릭터 이름, 입주와 공유 상태를 변경할 수 없다.

## 17. MVP에서 만들지 않는 기능

- 이메일 인증과 비밀번호 찾기
- 소셜 로그인
- 과거 날짜 일기 작성
- 일기와 캐릭터 다시 뽑기
- 공개 캐릭터 피드
- 댓글, 좋아요, 팔로우
- 다른 사용자 방 방문
- 가구 자유 배치(드래그)와 다른 사용자 방 꾸미기 구경 (가구 상점은 2026-11-02 범위에 추가됨)
- 캐릭터 간 대화와 충돌 물리
- 여러 방과 방 테마
- 감정 통계와 달력
- 캐릭터 성장과 진화
- SNS용 이미지 파일 자동 생성

## 18. 아직 결정하지 않은 사항

- 로컬 시연만 할지 공개 URL까지 배포할지
- 공개 배포 시 사용할 호스팅과 도메인

이 두 항목은 로컬 MVP 구현을 시작하는 데 방해가 되지 않는다.
