# MOZI 픽셀 소품 아트 가이드 및 현황 분석

작성일: 2026-11-05  
범위: 분석 및 제작 명세서 작성만 수행. 현재 소품 에셋과 생성 코드는 수정하지 않음.

## 1. 조사 요약

- 프론트엔드 소품 ID는 `frontend/src/characters/pixel/decorations.ts`의 `DecorationId`와 `DECORATION_LABELS`에 정의되어 있다. 총 40종이다.
- 이 40종은 별도 PNG 파일이 아니라 같은 파일의 `ITEM_SPRITES`에 든 문자형 픽셀 격자(`rows`)와 색상표(`colors`)다. 각 픽셀은 64×64 캐릭터 캔버스에 직접 찍는다.
- 일반 소품 원본 격자는 폭 4~15, 높이 5~10 논리 픽셀이다. 10×10 이하인 대부분은 `renderCharacter.ts`의 `detailedDecorationSprite`에서 nearest-neighbor 방식으로 각 픽셀을 2×2로 키운다. 수면 모자는 이미 15×10이라 확대하지 않는다. 헤드폰은 예외로 `HEADPHONE_CUP`과 밴드를 별도로 그린다.
- 기본 소품 외곽선 색은 `#3a2a40`이다. 색상 팔레트는 소품별로 있으나 모든 소품이 명확히 분리된 기본색·밝은 면·그림자·강조색 4역할을 갖춘 것은 아니다.
- 기본 배치 모드는 `hand`, `head`, `around` 세 가지다. 소품 대부분은 손 위치에 찍히며, 얼굴과 겹치지 않는 슬롯을 찾는 `around` 방식은 일부만 쓴다. HEAD/HAND의 현재 좌표와 렌더링 방식은 `renderCharacter.ts`의 `drawDecoration`에 구현되어 있다.
- 키워드 자동 연결은 프론트엔드 `KEYWORD_RULES`의 첫 일치 항목을 반환한다. 규칙 순서와 부분 문자열 검색에 의존하므로, 겹치는 키워드가 있으면 의도한 소품이 아닌 먼저 선언된 항목이 선택될 수 있다.
- 사용자가 제공한 미리보기와 연결되는 `FriendDemoPage`/`friends.ts` 경로에는 표시 문제도 있었다. 일반 데모(`soft=false`)에서는 소품 자체를 그리지 않는 조건이 있어 감정 반짝이나 머리 모양이 소품처럼 보일 수 있었다. 소품은 현재 크기를 유지하면서 미리보기 양쪽 모드에서 실제 소품을 표시하도록 수정했다. 작은 소품을 일괄 확대하는 접근은 식별성을 해결하지 못한다는 사용자 피드백에 따라 되돌렸다.
- 수면 모자와 맥주잔은 기존 `ITEM_SPRITES`를 보존하고 `ITEM_SPRITES_V2`에 별도 새 시안을 추가했다. 두 시안은 기존 논리 격자 크기(수면 모자 15×10, 맥주잔 8×7)를 유지한다. 현재는 사용자의 요청으로 실제 사용자 캐릭터의 소품 렌더링과 백엔드 신규 생성을 비활성화했고, `FriendDemoPage`의 40종 소품 전시도 제거했다. 기존 에셋/저장 데이터는 되돌릴 수 있도록 보존한다.
- 백엔드 `backend/app/services/character_generator.py`의 `OBJECT_DECORATIONS`에는 19개 소품만 직접 연결되어 있다. 그 외에는 분석 키워드 범주를 7개 `ACCESSORY_PARTS`로 치환한다. 따라서 프론트엔드 미리보기에서 선택할 수 있는 40종과 실제 저장되는 일기 캐릭터 소품 후보가 일치하지 않을 수 있다. 이번 문서 작업에서는 로직을 바꾸지 않았다.
- 캐릭터 DB 모델(`backend/app/models/character.py`)은 `render_spec` JSON을 저장하고, `character_generator.py`는 `decoration_id`, `objects`, `seed`, `renderer_version` 등을 그 안에 기록한다. `renderStoredCharacter.ts`는 저장된 명세를 기존 렌더러로 다시 그린다. 즉 DB에 소품 PNG를 저장하는 구조라기보다 렌더링 명세를 저장해 재현하는 구조다. `canvasExport.ts`는 필요할 때 캔버스를 이미지로 내보내는 기능이고, 그 자체가 서버 영구 저장은 아니다. 공유·도감·방에서 소품 표시가 유지되는지는 저장된 렌더 명세와 렌더러 버전 호환에 달려 있다.
- `frontend/public/assets/character-prototype/parts/decorations/`에는 이전 프로토타입용 PNG 5개(`coffee.png`, `crown.png`, `hearts.png`, `questions.png`, `rain_cloud.png`)가 있다. 현재 40종 전체의 원본은 이 PNG 폴더가 아니라 TypeScript 픽셀 격자다. 원본 파일은 보존한다.

## 2. 우선 개선 대상 5종

아래 순위는 현재 격자와 코드상 특징 부품을 검토해 정한 제작 우선순위다. 아직 이름을 가린 사용자 식별 테스트를 진행한 결과는 아니다.

| 순위 | 소품 | 현재 식별성 문제 | 개선 시 반드시 보일 부품 |
|---:|---|---|---|
| 1 | 수면 모자 (`sleepCap`) | 사용자가 제공한 화면에서 모자가 머리 위 작은 삼각 덩어리처럼 보여, 늘어진 수면 모자와 방울이 한눈에 읽히지 않는다. | 머리를 감싸는 밑단, 한쪽으로 늘어진 천 끝, 끝의 둥근 방울, 천 접힘 |
| 2 | 헤드폰 (`headphones`) | 기존 프로토타입은 머리 위 밴드가 거의 직선이고 이어컵이 귀처럼 튀어나와 헤드폰 착용 형태가 분명하지 않다. | 머리 위 아치형 밴드, 좌우 이어컵, 이어패드와 밴드 연결부 |
| 3 | 꽃 (`flower`) | 원본 스프라이트가 4×7이라 일반 프로토타입에서 매우 작고, 꽃잎·중심·줄기 구분이 약해 별/장식 점처럼 보일 수 있다. | 중심 수술, 겹쳐 보이는 둥근 꽃잎, 줄기와 잎 또는 머리 장식 위치 |
| 4 | 티켓 (`ticket`) | 8×5의 작은 직사각형이며 티켓 특유의 절취선·입장 정보·stub 구획이 없어 표나 쿠폰처럼 보일 수 있다. | 양 끝 절취 홈, 본체와 분리되는 stub, 날짜/좌석 표시 중 하나 |
| 5 | 한 끼 (`meal`) | 8×7 격자에서 그릇 테두리와 내용물 경계가 작고, 음식 종류가 구분되지 않아 일반 그릇처럼 보일 수 있다. | 그릇 입구와 깊이, 밥/반찬처럼 구분되는 재료 2종 이상, 받침 또는 젓가락 |

상위 3종은 사용자가 직접 확인한 미리보기에서 식별이 어렵다고 지적한 대상이다. 티켓과 한 끼는 코드 격자 검토로 추가한 후보이며, 아직 사용자 식별 테스트 결과는 아니다. 개선본은 기존 데이터를 덮어쓰지 않고 별도 버전으로 만들며, 원본/개선본을 나란히 비교하는 것이 다음 작업의 기준이다.

## 3. 공통 제작 명세

### 픽셀 및 화면 크기

- 기준 논리 격자: 소품 단독 제작은 기본 32×32, 세부 부품이 많은 것은 48×48까지 사용한다. 64×64는 캐릭터 캔버스와 조합 검증용이며, 모든 소품을 64×64로 그릴 필요는 없다.
- 현재 격자 크기는 아래 표의 `현재` 열에 적었다. 32/48 목표 캔버스 안에 실제 물체를 알맞게 배치하며, 확대만으로 디테일을 늘리지 않는다.
- 캐릭터에서 표시할 때는 논리 픽셀 정수 배율로 확대하고 nearest-neighbor를 사용한다. 픽셀 사이 보간, 흐림, 블러는 금지한다.
- 잘 안 보인다는 이유만으로 캐릭터 대비 소품이 차지하는 면적을 키우지 않는다. 먼저 실루엣, 주요 부품의 간격과 접점, 외곽선 대비, 내부 색면을 개선한다. 해상도를 높일 때도 캐릭터에 차지하는 실제 크기는 유지하고 내부 픽셀 설계만 더 정교하게 한다.
- 작은 표시 크기(소품 높이 약 8~14 논리 픽셀)에서도 특징 부품이 남도록 축소 검증한다.

### 팔레트와 조명

- 기본 광원은 좌상단으로 통일한다. 팔레트는 최소 외곽선, 기본색, 밝은 면, 그림자, 필요한 강조색 역할을 분명히 지정한다.
- 재질을 구별한다. 예: 유리는 가장자리 반사와 투명/액체 경계, 금속은 좁은 밝은 선, 천·가죽은 넓은 면과 어두운 측면, 음식은 재료별 색 블록.
- 소품 고유 외곽선은 MOZI의 짙은 외곽선과 어울리게 유지한다. 무작위 색상 노이즈는 쓰지 않는다.

### 배치와 복잡도

| 표기 | 의미 | 권장 기본 배치 |
|---|---|---|
| HEAD | 머리 착용/머리 위 장식 | 정수리 anchor. 얼굴 위로 내려오지 않게 함 |
| FACE | 얼굴에 착용 | 눈·눈썹 안전 영역 바깥, 좌우 균형 유지 |
| HAND | 손에 들기 | 캐릭터 오른쪽 또는 지정 손 anchor. 본체와 손 접점을 명확히 함 |
| BODY | 몸에 착용 | 몸통의 얼굴 아래쪽 안전 영역 |
| SIDE | 옆에 배치 | 좌우 여백 슬롯. 작은 소품은 캐릭터와 약간 겹쳐도 됨 |
| BACK | 뒤 레이어 | 캐릭터 렌더 전에 찍어 몸통 외곽을 가리지 않음 |

현재 구현 앵커는 HEAD/HAND/AROUND뿐이다. 표의 권장 모드는 제작 목표를 나타내며, 실제 변경 단계에서 FACE/BODY/SIDE/BACK을 새로 구현할 경우 기존 렌더·저장 호환성을 함께 확인한다. 얼굴을 가릴 가능성이 있는 소품은 선택적으로 생략한다.

## 4. 40종 소품별 제작 명세

`현재 격자`는 TypeScript 원본 픽셀 행렬의 너비×높이이며, `목표`는 개선본 단독 스프라이트의 권장 논리 캔버스다. 우선순위 P0은 다음 5종, P1은 식별 부품·재질 표현을 우선 보강할 대상, P2는 현재 구조를 살려 다듬을 대상이다. 배치 비율은 캐릭터 높이 대비 소품의 대략적인 시각적 크기다.

| ID / 이름 | 분류 · 현재 격자 → 목표 | 권장 시점 · 핵심 식별 부품 | 팔레트 · 명암 방향 | 배치 · 크기 | 현재 문제 및 우선순위 |
|---|---|---|---|---|---|
| `coffee` 커피 | 음료 · 7×9 → 32×32 | 3/4 정면; 컵 몸체, 윗면/커피, 손잡이, 김 | 크림·커피 갈색·하이라이트; 좌상단 밝고 우하단 어둡게 | HAND, 높이 24~32% | 손잡이/김이 작은 크기에서 분리되는지 확인. P1 |
| `drink` 음료 | 음료 · 6×10 → 32×32 | 정면 3/4; 컵 본체, 뚜껑/입구, 액체선, 빨대 | 컵 재질별 4~5색, 액체는 별도 강조색; 좌상단 광원 | HAND, 28~36% | 컵보다 빨대와 세로 막대처럼 보일 위험. P0 |
| `beer` 맥주잔 | 음료 · 8×7 → 8×7 유지 | 3/4 정면; 잔, 손잡이 구멍, 액면, 거품 | 맥주 금색, 흰 거품, 유리 반사, 짙은 가장자리 | HAND, 현 크기 유지 | 새 시안은 거품과 C형 손잡이를 보강했다. 개발용 비교본만 추가했고 실제 서비스 적용은 미승인. P0 |
| `book` 책 | 학습 · 8×7 → 32×32 | 약간 펼친 정면; 표지, 책등, 페이지 층, 책갈피 | 표지색/종이색/책등 그림자; 좌상단 | HAND, 25~34% | 현재 단단한 직사각 표지로 닫힌 책인지 노트인지 구분 보강. P1 |
| `headphones` 헤드폰 | 음악 · 특수 도형(컵 3×6, 밴드 동적) → 현 점유 크기 내 픽셀 재설계 | 정면; 머리 곡선 위 아치형 밴드, 좌우 이어컵, 패드/힌지 | 밴드·패드·힌지의 명도 대비; 좌상단 광원 | HEAD, 현 크기 유지 | 직선에 가까운 밴드와 컵 연결이 약함. 크기 대신 아치와 이어컵 구조를 분명히 함. P0 |
| `flower` 꽃 | 자연 · 4×7 → 같은 점유 폭 안에서 픽셀 재설계 | 정면; 꽃잎, 중심 수술, 줄기, 잎 | 꽃잎 밝은 면/중간/그림자, 중심, 녹색 잎 | HEAD, 현 크기 유지 | 꽃잎과 중심이 뭉쳐 별/점처럼 보일 수 있음. 덩치를 키우지 말고 꽃잎·중심 대비를 재설계. P0 |
| `heart` 하트 | 감정 장식 · 7×6 → 32×32 | 정면; 좌우 둥근 엽, 중앙 골, 아래 꼭짓점, 광택 | 핑크 기본/밝은 면/짙은 테두리 | SIDE, 16~24% | 작은 하트 단일 모티프. 캐릭터 표정과 겹치지 않게 관리. P2 |
| `gamepad` 게임패드 | 게임 · 8×7 → 32×32 | 정면; 좌우 손잡이, 십자키, 버튼 2개, 중앙 연결부 | 본체 2톤, 어두운 틈, 버튼 강조색 | HAND, 25~34% | D-pad와 버튼 배열을 확실히 분리할 필요. P1 |

## 5. 개선 제작 시 공통 품질 검증

각 대상은 기존 버전과 개선 버전을 함께 보존한 뒤 아래 순서로 확인한다.

1. **원본 격자 보기:** 논리 픽셀을 8~12배로 nearest-neighbor 확대해 외곽선, 색 구획, 잡음을 확인한다.
2. **이름 가린 식별 보기:** 이름과 키워드 설명 없이 소품만 보여 주고 5명 이상에게 무엇인지 짧게 묻는다. 4명 이상이 의도한 사물을 맞히지 못하면 형태를 다시 다듬는다. 이는 다음 구현 단계의 검증 제안이며, 현재 수행한 테스트가 아니다.
3. **캐릭터 장착 보기:** 기존 64×64 캐릭터에 실제 앵커로 붙이고 얼굴 가림, 외곽선 충돌, 부착 지점을 점검한다.
4. **실제 크기 보기:** 도감 카드와 감정 방에서 보이는 작은 크기로 확인한다. 단독 확대본만 통과하고 실제 크기에서 식별되지 않는 소품은 승인하지 않는다.
5. **재현/호환 확인:** 동일 저장 명세로 같은 결과를 다시 렌더하고, 구형 `renderer_version` 캐릭터와 공유 화면을 확인한다.

## 6. 다음 제작 단계 제안

1. 우선 5종(`ticket`, `meal`, `beach`, `drink`, `beer`)을 별도 `v2` 스프라이트로 제작한다.
2. 개발 갤러리에 원본/개선본, 단독 확대, 캐릭터 장착, 이름 숨기기 스위치를 제공한다.
3. 작은 크기 식별성과 캐릭터 조화를 확인한 뒤 기준을 승인받는다.
4. 나머지 35종을 P1/P2 순으로 확장한다.
5. 마지막으로 프론트 키워드 규칙과 백엔드 19종 연결을 정리하되, 기존 저장 데이터·공유 외형은 버전 호환을 유지한다.

## 7. 이번 단계에서 하지 않은 것

- 기존 소품 행렬, 팔레트, 키워드 매핑, 렌더링, DB 저장 방식을 수정하지 않았다.
- 기존 PNG 및 픽셀 소품을 삭제하거나 덮어쓰지 않았다.
- 새 소품 이미지나 개선본을 만들지 않았다.
- 이름을 가린 식별 테스트, 화면 캡처 비교, 빌드 및 테스트는 실행하지 않았다. 이 단계는 코드 조사와 제작 명세서 작성만을 위한 것이다.
