# MOZI MVP 기획서

## 1. 문서 목적

이 문서는 5일 안에 시연 가능한 감정 기록 웹 서비스 **MOZI(모지)**의 MVP 범위와 동작 규칙을 정리한 기준 문서다.

MOZI는 사용자가 오늘의 일기를 작성하면 AI가 감정을 분석하고, 그 결과를 바탕으로 감정 몬스터를 생성하는 참여형 감정 기록 서비스다. 생성된 캐릭터는 도감에 쌓이고, 사용자가 선택한 캐릭터들은 메인 화면의 감정 방에서 살아 움직인다.

이 문서에 없는 기능은 MVP에 임의로 추가하지 않는다. 공개 배포 방식은 추후 결정한다.

## 2. 서비스 목표

기존 감정 일기는 사용자가 몇 가지 표정 이모티콘 중 하나를 먼저 선택한 뒤 글을 작성하는 경우가 많다. 이 방식은 표현할 수 있는 감정이 제한되고 반복 사용의 재미가 약하다.

MOZI는 이 순서를 반대로 만든다.

```text
오늘의 일기 작성
→ AI가 복합 감정 분석
→ 감정에 맞는 캐릭터 생성 또는 기존 캐릭터 재등장
→ 도감에 기록
→ 감정 방에서 캐릭터와 다시 만남
```

핵심 목표는 다음과 같다.

- 사용자가 감정을 직접 고르지 않아도 일기 문맥에서 감정을 발견한다.
- 단순한 5가지 표정이 아닌 다양한 복합 감정과 강도를 캐릭터로 표현한다.
- 비슷한 감정이 반복되면 같은 캐릭터가 다시 찾아오게 해 애착을 만든다.
- 일기 쓰기에 랜덤 생성, 수집, 꾸준한 재방문의 재미를 더한다.

## 3. 주요 사용자

- 일상과 감정을 기록하고 싶은 20~30대 사용자
- 캐릭터 꾸미기와 수집형 콘텐츠를 좋아하는 사용자
- 랜덤한 결과를 만나는 경험을 좋아하는 사용자
- 기존 감정 이모티콘보다 더 다양한 감정 표현을 원하는 사용자

## 4. 핵심 제품 구조

MOZI의 네 가지 핵심 공간은 다음과 같다.

| 공간 | 역할 |
| --- | --- |
| 나의 감정 방 | 선택한 감정 캐릭터들이 살아 움직이는 메인 화면 |
| 오늘의 일기 | 하루 한 번 일기를 작성하고 캐릭터를 탄생시키는 공간 |
| 캐릭터 도감 | 지금까지 만난 캐릭터와 과거 일기를 다시 보는 공간 |
| 입주 관리 | 도감의 캐릭터 중 최대 5마리를 감정 방에 배치하는 공간 |

## 5. 핵심 사용자 흐름

### 5.1 처음 방문한 사용자

```text
랜딩 화면
→ 회원가입
→ 로그인
→ 나의 감정 방
→ 오늘의 일기 작성
→ AI 감정 분석
→ 캐릭터 공개
→ 도감 자동 저장
→ 원하는 경우 감정 방에 직접 입주
```

### 5.2 다시 방문한 사용자

```text
로그인
→ 나의 감정 방
→ 입주 캐릭터 감상
→ 오늘의 일기 작성 또는 오늘의 캐릭터 확인
→ 도감에서 과거 캐릭터와 일기 확인
```

### 5.3 캐릭터 공유

```text
캐릭터 상세 화면
→ 공유하기
→ 전용 링크 생성
→ 친구에게 링크 전달
→ 친구가 로그인 없이 캐릭터 자랑 카드 확인
```

## 6. MVP 기능 요구사항

### 6.1 회원가입과 로그인

- 이메일, 비밀번호, 닉네임으로 회원가입한다.
- 이메일 인증 없이 가입 직후 로그인할 수 있다.
- 가입 성공 후 로그인 화면으로 이동한다.
- 이메일은 올바른 형식이어야 하며 중복될 수 없다.
- 비밀번호는 8~64자로 제한한다.
- 비밀번호 원문은 저장하지 않고 안전하게 해시 처리한다.
- 닉네임은 1~20자로 제한한다.
- 닉네임에는 한글, 영문, 숫자, 밑줄만 사용할 수 있다.
- 닉네임은 다른 사용자와 중복될 수 없다.
- 가입 실패 시 이메일과 닉네임은 유지하고 비밀번호만 지운다.
- 로그인 상태는 HTTP-only 세션 쿠키로 유지한다.
- 로그인하지 않은 사용자는 개인 일기, 도감, 감정 방에 접근할 수 없다.
- MVP에는 이메일 인증, 비밀번호 찾기, 소셜 로그인을 포함하지 않는다.

### 6.2 랜딩 화면과 로그인 후 메인 화면

로그인하지 않은 방문자에게는 다음을 보여준다.

- MOZI 서비스 소개
- 감정 몬스터와 감정 방 미리보기
- 회원가입 버튼
- 로그인 버튼

로그인한 사용자에게는 `나의 감정 방`을 메인 화면으로 보여준다.

- 정면에서 바라보는 2D 픽셀 방
- 입주한 캐릭터 최대 5마리
- 오늘 일기 작성 여부
- `일기 쓰기`, `캐릭터 도감`, `입주 관리` 메뉴
- 계정 설정과 로그아웃
- 오늘 일기를 이미 작성했다면 `일기 쓰기` 대신 `오늘의 캐릭터 보기` 안내

### 6.3 오늘의 일기

- 한국 시간 기준 오늘 날짜의 일기만 작성할 수 있다.
- 사용자 한 명당 하루에 일기 하나만 작성할 수 있다.
- 과거 날짜를 선택하거나 빠진 날짜를 채우는 기능은 MVP에 포함하지 않는다.
- 일기는 앞뒤 공백을 제외하고 10~2,000자로 제한한다.
- 일기 제목은 선택 입력이며, 입력하는 경우 앞뒤 공백을 제외하고 100자 이하로 제한한다.
- 입력 화면에 현재 글자 수를 표시한다.
- 캐릭터 생성 전에는 일기를 자유롭게 수정할 수 있다.
- 생성 버튼을 누르면 수정 불가 안내와 최종 확인을 보여준다.
- 생성이 시작된 뒤에는 일기, 분석 결과, 캐릭터를 하나의 확정 기록으로 묶는다.
- 캐릭터 생성 후 일기는 읽기만 가능하고 수정할 수 없다.
- 새로고침, 중복 클릭, 네트워크 재시도로 캐릭터가 여러 개 생성되지 않게 한다.
- 오늘 기록을 삭제하더라도 같은 날 새 일기와 캐릭터를 다시 만들 수 없다.
- 삭제 후 재생성을 막기 위해 일기 내용이 아닌 최소한의 일일 생성 여부를 유지한다.

### 6.4 AI 감정 분석

실제 OpenAI API 분석을 기본으로 사용한다.

- API 키는 서버의 `.env`에서만 관리한다.
- API 키를 브라우저, 코드, 문서, Git, 로그에 노출하지 않는다.
- 일기에서 기본 감정·상태 16개의 강도를 0~100으로 분석한다.
- 기본 감정의 조합과 문맥에서 세부 감정·상태를 탐지한다.
- 주요 감정, 보조 감정, 전체 에너지, 중요 사건, 사물 키워드를 추출한다.
- 결과는 정해진 JSON 구조로 반환한다.
- 사용자의 화면에는 캐릭터 구성에 사용된 의미 있는 상위 감정만 최대 3개 표시한다.
- 표시 비율은 이해하기 쉽도록 합계 100%로 정규화한다.
- 심리 진단처럼 단정하지 않고 `AI가 오늘의 일기를 이렇게 해석했어요`라고 표현한다.

예시:

```text
AI가 오늘의 일기를 이렇게 해석했어요.
설렘 55% · 불안 30% · 기쁨 15%
```

#### AI 실패 처리

실제 AI 분석이 실패하면 다음 선택지를 함께 보여준다.

- `다시 시도`: 실제 AI API를 다시 호출한다.
- `데모 분석으로 계속하기`: 규칙 기반 분석 결과로 진행한다.

사용자 선택 없이 실제 분석을 데모 결과로 몰래 바꾸지 않는다. 데모 결과로 생성한 기록에는 데모 사용 여부를 저장하고 화면에도 작게 표시한다.

### 6.7 감정 강도 5단계

| 점수 | 단계 | 캐릭터 표현 |
| ---: | --- | --- |
| 0~19 | 미약 | 눈썹이나 입이 조금 변함 |
| 20~39 | 약함 | 감정이 알아보일 정도의 표정 |
| 40~59 | 보통 | 눈썹, 눈, 입이 모두 변함 |
| 60~79 | 강함 | 표정이 과장되고 감정 효과가 추가됨 |
| 80~100 | 극대화 | 강한 모션과 특별 효과가 추가됨 |

감정 강도는 얼굴 파츠뿐 아니라 움직임의 속도, 크기, 대기 행동에도 영향을 준다.

### 6.8 캐릭터 생성 알고리즘

캐릭터는 완성 이미지를 매번 AI로 그리지 않고, 사전에 만든 SVG 픽셀 파츠를 겹쳐 생성한다.

#### 레이어 순서

```text
그림자
→ 몸통 형태와 색상
→ 눈썹
→ 눈
→ 입
→ 키워드 장식
→ 감정 효과
→ 돌연변이 요소
```

#### 생성 우선순위

1. 주요 감정이 기본 색상, 얼굴과 행동 유형을 정한다.
2. 보조 감정이 눈썹, 눈, 입 중 일부를 바꾼다.
3. 세부 상태가 특징적인 표정이나 효과를 추가한다.
4. 감정 강도가 표정과 모션의 세기를 결정한다.
5. 일기 키워드가 커피, 헤드폰, 우산 같은 임시 장식을 정한다.
6. 사용자별 랜덤 시드가 몸통, 귀, 꼬리, 뿔과 돌연변이를 정한다.

#### 같은 캐릭터의 재등장

매일 무조건 새로운 캐릭터를 만들지 않는다. 비슷한 감정 분석이 반복되면 기존 캐릭터가 다시 등장한다.

MVP에서는 다음 값을 조합한 `감정 지문`을 사용한다.

- 주요 감정
- 주요 감정의 강도 단계
- 가장 강한 보조 감정
- 가장 뚜렷한 세부 상태
- 전체 에너지 단계

같은 사용자에게 동일한 감정 지문이 나오면 같은 캐릭터 ID를 사용한다. 캐릭터의 기본 외형은 유지하고, 해당 날짜의 강도, 장식과 대사는 별도의 만남 기록으로 저장한다. 다른 사용자가 비슷한 일기를 작성해도 사용자별 시드가 달라 서로 다른 외형이 생성될 수 있다.

#### 같은 캐릭터가 유지하는 요소

- 몸통 형태와 기본 색상
- 기본 눈썹, 눈, 입
- 귀, 뿔, 꼬리와 돌연변이
- 캐릭터 이름
- 기본 행동 성격

#### 만날 때마다 달라질 수 있는 요소

- 감정 강도에 따른 표정의 과장 정도
- 움직임의 속도와 크기
- 일기 키워드에 따른 임시 장식
- 클릭했을 때 표시되는 감정 대사

생성된 캐릭터 설계도에는 파츠 ID, 색상, 랜덤 시드와 알고리즘 버전을 저장한다. 서비스 코드를 바꾼 뒤에도 기존 캐릭터가 같은 모습으로 표시되어야 한다.

### 6.9 캐릭터 결과 화면

- 캐릭터와 기본 모션
- MOZI가 자동 생성한 기본 이름
- 사용자에게 보여줄 상위 감정 최대 3개
- 짧은 캐릭터 특징 설명
- `도감에서 보기` 버튼
- 방에 빈자리가 있으면 `방에 입주시키기` 버튼
- 공유하기 버튼

캐릭터는 생성 즉시 도감에 자동 저장한다. 별도의 `도감에 저장하기` 버튼은 제공하지 않는다.

### 6.10 캐릭터 이름

- MOZI가 감정과 장식을 바탕으로 기본 이름을 자동 생성한다.
- 사용자는 캐릭터 상세 화면에서 이름을 변경할 수 있다.
- 이름은 앞뒤 공백을 제외하고 1~12자로 제한한다.
- 이름은 여러 번 변경할 수 있다.
- 이름을 변경해도 외형과 감정 기록은 바뀌지 않는다.
- 변경한 이름은 기존 공유 링크에도 반영한다.

### 6.11 캐릭터 도감과 만남 기록

- 도감은 캐릭터를 카드 형태로 보여준다.
- 같은 캐릭터가 재등장하면 중복 카드를 만들지 않는다.
- 기존 카드에 만난 횟수, 처음 만난 날, 최근 만난 날을 쌓는다.
- 캐릭터 상세 화면에는 만났던 날짜 목록을 최신순으로 보여준다.
- 날짜를 선택하면 당시 일기 원문, 상위 감정, 세부 상태, 장식과 대사를 확인할 수 있다.
- 일기와 분석 결과는 계정 소유자만 볼 수 있다.
- 하루의 만남 기록을 삭제하면 해당 날짜 기록만 제거한다.
- 다른 만남이 남아 있으면 캐릭터 카드는 유지한다.
- 모든 만남이 삭제되면 캐릭터를 도감과 감정 방에서 제거한다.

### 6.12 나의 감정 방

- 정면에서 바라보는 2D 픽셀 방으로 만든다.
- MVP에서는 기본 방 배경 한 종류만 제공한다.
- 방에는 최대 5마리까지 입주시킬 수 있다.
- 새 캐릭터는 방에 자동 입주하지 않는다.
- 사용자가 `입주 관리`에서 직접 입주와 퇴실을 선택한다.
- 5마리가 입주한 상태에서는 기존 캐릭터를 퇴실시킨 뒤 새 캐릭터를 선택한다.
- 퇴실해도 캐릭터와 만남 기록은 도감에 남는다.
- 입주 상태는 다시 로그인해도 유지한다.
- 캐릭터의 세부 좌표는 화면을 다시 열 때 달라질 수 있다.

#### 행동 유형

36가지 표현마다 완전히 다른 이동 로직을 만들지 않고, 다음 6가지 행동 유형을 재사용한다.

| 행동 유형 | 감정 예시 | 이동과 대기 행동 |
| --- | --- | --- |
| 활발형 | 기쁨, 설렘, 기대감 | 빠르게 이동하고 제자리에서 통통 뜀 |
| 평온형 | 평온, 안도, 만족감 | 천천히 이동하고 편하게 쉼 |
| 지침형 | 피로, 지루함 | 느리게 이동하고 졸거나 앉음 |
| 정지형 | 무기력, 현타, 체념 | 거의 움직이지 않고 구석에 머묾 |
| 격앙형 | 분노, 짜증, 답답함 | 짧고 빠르게 오가며 발을 구름 |
| 불안정형 | 불안, 혼란, 멘붕 | 이동 중 방향을 자주 바꾸고 두리번거림 |

복잡한 게임 엔진, 물리 충돌과 정교한 길 찾기는 사용하지 않는다. 방 안의 허용 영역에서 일정 시간마다 목표 좌표를 선택하고 CSS/SVG 애니메이션으로 이동한다.

### 6.13 캐릭터 대사

- 방의 캐릭터를 누르면 짧은 말풍선을 보여준다.
- 대사는 추가 AI 호출 없이 감정별로 미리 준비한 후보에서 선택한다.
- 주요 감정, 세부 상태와 강도에 맞는 안전한 문장을 사용한다.
- 일기 원문, 개인 이름과 구체적인 사건을 대사에 포함하지 않는다.
- 말풍선은 몇 초 뒤 자동으로 닫힌다.

### 6.14 캐릭터 공유

- 캐릭터 상세 화면에 `공유하기` 버튼을 제공한다.
- 사용자가 공유를 선택하면 추측하기 어려운 전용 링크를 생성한다.
- 친구는 로그인하지 않아도 공유 페이지를 볼 수 있다.
- 링크에는 사용자 ID와 이메일을 노출하지 않는다.
- 사용자는 공유를 취소할 수 있으며 취소 즉시 링크를 비활성화한다.
- 공개 피드, 댓글, 좋아요, 팔로우는 MVP에 포함하지 않는다.

공유 페이지에는 다음만 표시한다.

- `OOO님이 새로운 감정 몬스터를 공유했어요!` 문구
- 공유자의 현재 닉네임
- 캐릭터 모습과 모션
- 캐릭터 이름
- MOZI 서비스 이름
- `나도 감정 몬스터 만들기` 버튼

다음 정보는 공유하지 않는다.

- 일기 원문과 요약
- 일기 작성 날짜
- 감정 점수와 세부 분석
- 사건과 키워드
- 이메일과 계정 정보
- 다른 캐릭터와 전체 도감

### 6.15 기록 삭제

- 확정된 일기와 캐릭터는 수정할 수 없지만 삭제할 수 있다.
- 삭제 전 `삭제하면 복구할 수 없습니다`라는 확인을 보여준다.
- 삭제하면 해당 일기 원문, 분석 결과, 만남 기록과 날짜별 장식을 제거한다.
- 캐릭터에게 다른 만남이 없으면 캐릭터, 입주 상태와 공유 링크도 함께 제거한다.
- 삭제 후에도 같은 날 일기와 캐릭터를 다시 생성할 수 없다.

### 6.16 계정 설정과 회원 탈퇴

#### 닉네임 변경

- 닉네임은 1~20자로 변경할 수 있다.
- 한글, 영문, 숫자, 밑줄만 사용할 수 있다.
- 다른 사용자와 중복될 수 없다.
- 변경된 닉네임은 기존 공유 페이지에도 반영한다.

#### 회원 탈퇴

1. 삭제될 데이터를 안내한다.
2. 현재 비밀번호를 다시 입력한다.
3. 정해진 탈퇴 확인 문구를 입력한다.
4. 최종 확인 후 계정과 데이터를 삭제한다.
5. 로그인 세션을 종료하고 랜딩 화면으로 이동한다.

탈퇴하면 모든 일기, 감정 분석, 캐릭터, 만남 기록, 감정 방 입주 정보와 공유 링크를 삭제한다. 탈퇴 후 데이터는 복구할 수 없다.

## 8. 디자인 원칙

- 크림색 계열의 따뜻한 배경을 사용한다.
- 보라색을 MOZI의 대표 색상으로 사용한다.
- 캐릭터는 감정에 맞는 파스텔 색상을 사용한다.
- 캐릭터에는 굵고 어두운 픽셀 외곽선을 사용한다.
- 카드와 버튼은 둥글고 친근하게 표현한다.
- 제목과 강조 요소에는 픽셀 느낌을 적용한다.
- 일기와 본문에는 읽기 쉬운 일반 한글 글꼴을 사용한다.
- 모바일에서도 캐릭터 표정이 충분히 크게 보이게 한다.
- 부정적인 감정을 나쁘거나 실패한 상태처럼 표현하지 않는다.
- 움직임 감소 설정을 사용하는 환경에서는 과한 모션을 줄인다.

## 9. 권장 기술 구성

5일 MVP에서는 한 가지 단순한 구조를 유지한다.

| 구분 | 권장 기술 | 이유 |
| --- | --- | --- |
| 프론트엔드 | React, TypeScript, Vite | 빠른 화면 개발과 상태 관리 |
| 스타일 | Tailwind CSS | 반응형 UI를 빠르게 구성 |
| 캐릭터 | 레이어형 SVG | 파츠 조합, 색상 변경과 확대에 유리 |
| 모션 | CSS/SVG 애니메이션 | 게임 엔진 없이 가벼운 움직임 구현 |
| 백엔드 | Python, FastAPI | AI 연동과 구조화된 API 개발에 적합 |
| 데이터 접근 | SQLAlchemy | 사용자와 기록 관계를 명확하게 관리 |
| 데이터베이스 | Supabase PostgreSQL | 온라인 저장과 관계형 데이터 관리 |
| 인증 | 서버 발급 HTTP-only 세션 쿠키 | 브라우저에서 인증 정보를 직접 노출하지 않음 |
| AI | OpenAI API | 문맥 기반 복합 감정 분석 |
| 데모 분석 | 서버 규칙 기반 분석기 | API 없이도 시연 가능 |

공개 배포 서비스와 도메인은 아직 결정하지 않는다. 로컬 실행과 추후 공개 배포가 모두 가능하도록 환경 변수를 사용한다.

## 11. 보안과 개인정보 원칙

- API 키와 비밀번호 원문을 코드, 문서, Git과 로그에 넣지 않는다.
- 실제 비밀값은 `.env`에만 저장하고 `.env.example`에는 변수 이름만 기록한다.
- 일기 데이터는 기본 비공개다.
- 모든 개인 조회 API에서 현재 사용자 소유권을 서버가 확인한다.
- 클라이언트 화면에서 버튼을 숨기는 것만으로 권한을 처리하지 않는다.
- 공유 링크에는 일기와 감정 분석을 포함하지 않는다.
- 공유 토큰은 순차적인 ID 대신 추측하기 어려운 값을 사용한다.
- AI 분석 전에 일기 내용이 외부 AI 서비스로 전송될 수 있음을 안내한다.
- AI 결과가 의학적·심리학적 진단이 아님을 명확히 한다.
- 삭제와 회원 탈퇴는 명시적인 재확인 뒤 실행한다.

- [ ] 상위 감정 최대 3개만 간단하게 표시한다.
- [ ] 감정, 강도, 키워드와 랜덤 요소가 캐릭터 외형에 반영된다.
- [ ] 비슷한 감정 지문에서는 기존 캐릭터가 재등장한다.
- [ ] 캐릭터는 생성 즉시 도감에 자동 저장된다.
- [ ] 같은 캐릭터의 여러 만남이 한 카드에 누적된다.
- [ ] 캐릭터 이름을 변경할 수 있다.
- [ ] 캐릭터 상세 화면에서 날짜별 비공개 일기를 다시 볼 수 있다.
- [ ] 최대 5마리를 감정 방에 직접 입주·퇴실시킬 수 있다.
- [ ] 감정 방의 캐릭터가 행동 유형에 따라 움직이고 대사를 표시한다.
- [ ] 캐릭터만 보여주는 공유 링크를 만들고 취소할 수 있다.
- [ ] 공유 페이지에 일기와 감정 분석이 노출되지 않는다.
- [ ] 기록을 삭제할 수 있으며 같은 날 다시 생성할 수 없다.
- [ ] 닉네임을 변경할 수 있다.
- [ ] 비밀번호 재확인 후 회원 탈퇴할 수 있다.
- [ ] 모바일과 PC에서 핵심 흐름을 사용할 수 있다.
- [ ] API 키와 비밀번호 원문이 브라우저, Git과 로그에 노출되지 않는다.

## 15. 구현 시 주의할 위험 요소

### 파츠 호환성

모든 SVG 파츠는 같은 가상 캔버스, 기준 좌표, 픽셀 크기와 레이어 순서를 사용해야 한다. 파츠 수를 늘리기 전에 모든 조합이 자연스러운지 확인한다.

### 5일 범위 초과

회원, AI, 캐릭터 합성, 도감, 감정 방, 공유까지 포함되어 범위가 크다. 감정 방은 2D 좌표 이동으로 제한하고 게임 엔진, 충돌 물리와 가구 상호작용을 추가하지 않는다.

### AI 결과의 일관성

AI 응답은 반드시 서버에서 스키마 검증한다. 누락되거나 잘못된 점수에는 안전한 기본값을 적용하고, 분석 실패가 중복 캐릭터 생성을 일으키지 않게 한다.

### 비슷한 캐릭터 판정

초기에는 감정 지문 규칙으로 단순하게 시작한다. 실제 시연 데이터를 보며 너무 자주 같은 캐릭터가 나오거나 지나치게 새 캐릭터가 생기는지 조정한다.

### 개인정보

일기 원문과 감정 분석은 민감한 정보다. 공유, 로그, 오류 메시지와 관리자 도구에 원문이 불필요하게 노출되지 않도록 한다.
