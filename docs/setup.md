# MOZI 개발 환경 준비

## 1. 문서 목적

이 문서는 MOZI를 로컬에서 개발하기 위한 환경 기준과 준비 상태를 기록한다.

현재는 개발 계획의 Phase 7까지 구현된 상태다. 로컬 SQLite에서 전체 개발을 이어갈 수 있으며, Supabase PostgreSQL과 실제 OpenAI 호출 검증은 각각의 비밀값을 설정한 뒤 진행한다.

```powershell

```

Python은 여러 버전이 설치되어 있으므로 백엔드 명령에 `py -3.13`을 명시한다.

```powershell
py -3.13 --version
```

## 4. 환경 변수 준비

저장소의 `.env.example`을 복사해 로컬 `.env`를 만든다.

```powershell
Copy-Item -LiteralPath '.env.example' -Destination '.env'
```

실제 `.env`에는 다음 비밀값을 사용자가 직접 입력한다.

- `DATABASE_URL`: Supabase PostgreSQL 연결 문자열
- `SESSION_SECRET`: 충분히 긴 임의 문자열
- `OPENAI_API_KEY`: 실제 OpenAI API 키
- `OPENAI_MODEL`: 기본값 `gpt-6-luna`

실제 값은 채팅, 문서, 코드, Git과 화면 캡처에 넣지 않는다. `.gitignore`는 `.env`와 파생 환경 파일을 제외하고 `.env.example`만 추적하도록 설정되어 있다.

## 6. 설치와 실행 명령

### 처음 의존성을 준비할 때

```powershell
Set-Location frontend
npm.cmd install
```

```powershell
Set-Location backend
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m alembic upgrade head
```

### 백엔드 실행

```powershell
Set-Location backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

상태 확인 주소는 `http://localhost:8000/api/health`다. 개발 환경에서는 API 문서를 `http://localhost:8000/docs`에서 볼 수 있다.

### 프론트엔드 실행

다른 터미널에서 실행한다.

```powershell
Set-Location frontend
npm.cmd run dev
```

기본 주소는 `http://localhost:5173`이다.

### 휴대폰에서 보기 (같은 와이파이)

1. 백엔드를 네트워크에서도 접속할 수 있게 실행한다.

   ```powershell
   Set-Location backend
   .\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
   ```

2. 프론트엔드는 `npm.cmd run dev` 그대로 실행한다. `vite.config.ts`의 `server.host`가 네트워크 접속을 허용한다.
3. `ipconfig`의 IPv4 주소로 휴대폰 브라우저에서 `http://<IPv4 주소>:5173`을 연다.
4. Windows 방화벽 허용 창이 뜨면 "개인 네트워크"를 허용한다.

개발 모드에서는 사설 네트워크 주소(192.168.x.x, 10.x.x.x, 172.16~31.x.x)의 5173 포트만 백엔드 CORS에서 허용한다.
`http://` 주소에서는 브라우저 정책상 위치 권한(창문 날씨는 서울 기준), 링크 복사, 기본 공유 기능이 제한될 수 있다.

### 테스트와 빌드

```powershell
Set-Location backend
.\.venv\Scripts\python.exe -m pytest
```

```powershell
Set-Location frontend
npm.cmd run lint
npm.cmd run test
npm.cmd run build
```

## 7. 진행 결과

### Phase 0

- 기획 문서와 개발 계획의 기술 구성이 충돌하지 않는다.
- React + TypeScript + Vite와 FastAPI 기반으로 시작할 수 있다.
- Node.js, Python 3.13과 Git이 준비되어 있다.
- 프론트엔드와 백엔드 기본 포트를 사용할 수 있다.
- Python 3.13용 백엔드 핵심 패키지를 설치할 수 있는 버전이 확인되었다.
- 비밀값 파일은 아직 존재하지 않으며 실제 키도 환경 변수에 노출되어 있지 않다.
- Supabase 연결 문자열과 OpenAI 키는 실제 외부 서비스 검증 전에 사용자가 로컬 `.env`에 준비해야 한다.

### Phase 1

- React + TypeScript + Vite 프로젝트를 생성했다.
- Tailwind CSS와 MOZI 공통 색상·반응형 기본 스타일을 연결했다.
- 랜딩과 회원가입·로그인·감정 방 자리 표시 라우트를 만들었다.
- 공통 API 요청 함수와 보호 라우트 틀을 만들었다.
- FastAPI 앱과 `GET /api/health` 상태 확인 API를 만들었다.
- 프론트엔드에서 백엔드 연결 상태를 표시한다.
- 프론트엔드 린트, 테스트와 프로덕션 빌드가 통과했다.
- 백엔드 상태 API 테스트가 통과했다.
- 두 개발 서버를 실제로 실행해 프론트엔드 HTTP 200과 백엔드 `ok` 응답을 확인했다.

### Phase 2 로컬 구현

- PostgreSQL과 SQLite에서 함께 사용할 수 있는 SQLAlchemy 사용자·세션 모델을 만들었다.
- Alembic 초기 마이그레이션의 업그레이드·다운그레이드·재업그레이드를 확인했다.
- 비밀번호를 Argon2로 해시하고 원문을 저장하지 않는다.
- 무작위 세션 토큰의 해시만 DB에 저장하고 HTTP-only 쿠키로 로그인 상태를 유지한다.
- 회원가입, 로그인, 현재 사용자 조회, 로그아웃과 닉네임 변경 API를 만들었다.
- 회원가입, 로그인, 보호 라우트, 감정 방 빈 화면과 계정 설정 화면을 실제 API에 연결했다.
- 백엔드 테스트 7개와 프론트엔드 테스트 2개가 통과했다.
- 프론트엔드 린트와 프로덕션 빌드가 경고 없이 통과했다.
- 실제 개발 서버에서 가입, 쿠키 로그인, 사용자 조회, 닉네임 변경과 로그아웃을 확인했다.
- 통합 확인용 계정은 제거하고 마이그레이션만 적용된 빈 로컬 DB를 다시 만들었다.

Supabase `DATABASE_URL`이 아직 없어 실제 PostgreSQL 연결과 마이그레이션은 확인하지 못했다. 따라서 Phase 2 구현은 완료했지만 Supabase 검증은 대기 상태다. 다음 기능 구현은 로컬 DB로 계속할 수 있다.

### Phase 3

- 한국 시간 기준 사용자별 하루 한 번 일기를 저장하는 모델과 마이그레이션을 만들었다.
- 일기는 앞뒤 공백을 제거한 뒤 10~2,000자로 서버에서 다시 검사한다.
- 오늘 상태 조회와 오늘 일기 확정 API를 만들었다.
- 중복 제출은 새 기록을 만들거나 원문을 덮어쓰지 않고 기존 기록을 반환한다.
- 일기 작성, 글자 수, 최종 확인과 분석 대기 화면을 연결했다.
- 감정 방에서 오늘의 미작성·분석 대기 상태를 확인할 수 있다.
- AI 분석을 아직 연결하지 않았으며 일기는 `analyzing` 상태로만 확정된다.
- 백엔드 테스트 12개와 프론트엔드 테스트 3개가 통과했다.
- 새 마이그레이션의 업그레이드·다운그레이드·재업그레이드를 확인했다.
- 실제 서버에서 최초 생성과 중복 제출의 동일 ID·원문 보존을 확인했다.
- 통합 확인용 계정과 일기를 제거하고 빈 로컬 DB를 다시 만들었다.

Phase 3은 완료되었고 Phase 4 분석 기능으로 연결되었다.

### Phase 4

- 기본 감정 16개, 세부 상태 20개와 장식용 키워드 분류를 코드로 정의했다.
- OpenAI Responses API의 구조화 출력을 Pydantic 스키마로 검증하도록 연결했다.
- 실제 AI와 규칙 기반 데모 분석이 같은 데이터 형식으로 저장된다.
- 주요 감정은 최대 3개만 골라 화면 비율의 합이 100%가 되도록 표시한다.
- AI 분석 실패 시 일기는 보존하고 `다시 시도`와 `데모 분석으로 계속하기`를 명시적으로 제공한다.
- 감정 분석 모델과 세 번째 마이그레이션을 만들고 로컬 DB에 적용했다.
- 백엔드 테스트 17개와 프론트엔드 테스트 5개가 통과했다.
- 프론트엔드 린트와 프로덕션 빌드가 통과했다.
- API 키가 없는 실제 서버에서 `ai_failed` 상태와 데모 분석 완료, 표시 비율 합계 100%를 확인했다.
- 통합 확인용 계정과 일기는 검증 후 제거했다.

현재 로컬 환경에서는 실제 OpenAI 네트워크 호출을 아직 확인하지 못했다. 키를 채팅이나 코드에 붙이지 말고 프로젝트 루트의 `.env`에 직접 입력한 뒤 백엔드를 다시 실행해야 한다. 이후 개발은 데모 분석으로도 계속 진행할 수 있다.

### Phase 5

- 감정 강도 5단계와 명세 기반 감정 지문을 구현했다.
- 16개 기본 감정 모두에 고유한 눈썹·눈·입 표정 조합을 정의했다.
- 몸통 4종, 색상 8종, 돌연변이 5종과 키워드 장식 10종을 결정적 시드로 조합한다.
- 같은 사용자의 같은 감정 지문은 기존 캐릭터를 재사용하고 새 만남만 추가한다.
- 다른 사용자는 같은 감정 지문이라도 서로 다른 시드를 사용한다.
- 캐릭터와 만남을 분석 저장과 같은 데이터베이스 작업으로 자동 저장한다.
- SVG 캐릭터, 기본 감정 모션, 이름과 특징을 오늘 결과 화면에 연결했다.
- 새로고침 뒤에도 같은 캐릭터 ID와 외형이 유지되는 실제 API 흐름을 확인했다.
- 네 번째 마이그레이션을 로컬 DB에 적용했다.
- 백엔드 테스트 22개와 프론트엔드 테스트 5개가 통과했다.

Phase 5는 완료되었다. 다음 작업은 캐릭터 도감 목록·상세, 이름 변경과 날짜별 만남 조회를 만드는 Phase 6이다.

### Phase 6

- 사용자별 캐릭터 도감 목록과 최근 만남 순 정렬을 구현했다.
- 카드에서 현재 이름, 주요 감정, 만난 횟수와 최근 날짜를 표시한다.
- 캐릭터 상세에서 1~12자 이름 변경과 날짜별 만남 목록을 제공한다.
- 날짜를 선택하면 당시의 비공개 일기와 주요 감정 결과를 다시 볼 수 있다.
- 다른 사용자의 캐릭터 ID와 만남 ID를 입력해도 비공개 데이터에 접근할 수 없다.
- 만남 삭제 전 복구 불가와 마지막 만남 삭제 영향을 명시적으로 확인한다.
- 삭제한 날짜는 일기와 분석을 제거하되 다시 생성할 수 없도록 날짜 표식을 유지한다.
- 마지막 만남 삭제 시 해당 캐릭터도 도감에서 정리된다.
- 감정 방과 오늘 결과 화면에서 도감으로 이동할 수 있다.
- 백엔드 테스트 27개와 프론트엔드 테스트 7개가 통과했다.
- 프론트엔드 린트와 프로덕션 빌드가 통과했다.

Phase 6은 완료되었다. 다음 작업은 최대 5마리 입주, 감정별 움직임과 말풍선을 구현하는 Phase 7이다.

### Phase 7

- 도감에서 캐릭터를 입주·퇴실시키는 관리 화면을 구현했다.
- 서버와 화면 모두에서 감정 방 최대 5마리 제한을 적용했다.
- 반복 입주 요청은 중복 처리하지 않으며 다른 사용자의 캐릭터 입주 요청을 막는다.
- 정면형 픽셀 방에 창문, 소파, 선반, 러그와 바닥을 구성했다.
- 활발형, 평온형, 지침형, 정지형, 격앙형과 불안정형의 이동 확률·속도를 다르게 적용했다.
- 감정 강도에 따라 이동 빈도와 속도를 추가로 조절한다.
- 캐릭터를 누르면 일기 원문이나 개인정보가 없는 감정별 안전한 대사를 표시한다.
- 말풍선은 몇 초 뒤 자동으로 사라지고 키보드로도 캐릭터를 선택할 수 있다.
- 운영체제의 움직임 감소 설정에서는 자동 이동과 전환을 중지한다.
- 백엔드 테스트 30개와 프론트엔드 테스트 8개가 통과했다.
- 프론트엔드 린트와 프로덕션 빌드가 통과했다.

Phase 7은 완료되었다. 다음 작업은 일기와 감정 정보를 노출하지 않는 캐릭터 공유 링크를 구현하는 Phase 8이다.

### ngrok으로 보기 (와이파이 밖, https)

1. https://ngrok.com 에 가입하고 ngrok을 설치한 뒤, 대시보드에 나온 authtoken을 한 번 등록한다. 토큰은 코드나 문서에 적지 않는다.
   ```powershell
   winget install ngrok.ngrok
   ngrok config add-authtoken <대시보드의 토큰>
   ```
2. 백엔드(`--port 8000`)와 프론트엔드(`npm.cmd run dev`)를 평소처럼 켠다.
3. 새 터미널에서 프론트엔드만 터널로 연다.
   ```powershell
   ngrok http 5173
   ```
4. `Forwarding`에 나온 `https://….ngrok-free.app` 주소를 휴대폰 등에서 연다. 처음 한 번 나오는 ngrok 안내 화면에서 `Visit Site`를 누른다.

- ngrok 주소로 열면 프론트엔드가 `/api` 요청을 Vite 프록시(`vite.config.ts`)로 로컬 백엔드에 넘기므로 터널은 5173 하나만 있으면 된다.
- 주소를 아는 사람은 누구나 접속할 수 있으니 확인이 끝나면 `Ctrl + C`로 터널을 닫는다.
